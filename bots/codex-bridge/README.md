## 첨부파일

PDF 등 파일을 텍스트 없이 첨부해도 수신합니다. 파일은 `private/attachments/`에 저장하며 에이전트 입력에 실제 로컬 경로·파일명·크기·원본 메시지 ID를 전달합니다. PDF 텍스트를 릴레이 자체에서 추출하지는 않으며, 에이전트가 PDF 도구로 파일을 읽습니다. 암호·스캔·손상·읽기 도구 문제로 내용을 확인할 수 없으면 원인을 설명하도록 지시합니다.

같은 채널·스레드에서 “위 PDF를 요약해줘”라고 하면 최근 PDF가 붙은 메시지를 연결합니다. 한 메시지에 PDF가 여러 개면 모두 전달합니다. PDF 메시지에 직접 답글을 달면 그 파일을 우선합니다. 다른 스레드·채널·계정·발신자 범위의 캐시를 섞지 않습니다. 재시작 후에도 참조를 유지하며, 설치 전의 파일은 같은 채널·스레드의 최근 100개 메시지에서 허용된 발신자의 PDF를 조회합니다. 이를 위해 메시지 기록 보기 권한이 필요합니다.

작업 중 들어온 파일도 다운로드하여 보관하고, 다음 요청에서 이전 PDF로 참조할 수 있게 안내합니다. 용량 초과·시간 초과·HTTP 오류·잘못된 PDF 헤더·기록 조회 실패·이전 PDF 없음은 채널에 원인을 표시합니다. 만료된 Discord 링크는 원본 메시지를 다시 조회하여 한 번 갱신합니다. CDN URL이나 서명은 캐시에 저장하지 않습니다. `!new`는 대화와 캐시 참조를 초기화하지만 다운로드한 파일 자체는 지우지 않습니다. 최근 100개 기록에 남아 있는 PDF는 새 요청으로 다시 조회할 수 있습니다.

기본 한도는 파일당 25 MiB, 메시지당 5개, 다운로드 30초입니다. 기존 설정을 그대로 사용하며 `private/config.json`의 선택 항목 `attachments`로 조정할 수 있습니다:

```json
{"attachments":{"maxFileBytes":26214400,"maxFiles":5,"timeoutMs":30000,"historyLimit":100}}
```

다운로드 파일은 자동 삭제하지 않습니다. 필요 없어지면 릴레이를 멈춘 후 `private/attachments/`를 정리하세요. 다운로드 경로는 사용자가 지정한 자료로서 해당 요청에서 읽기만 허용하며, 자료 안의 지시를 시스템 지시로 취급하지 않습니다.

검증: `npm.cmd test`, `npm.cmd run check`.
설정은 `private/`, 의존성은 `node_modules/`에 저장합니다. 여행 앱 저장소에는 추가하지 않습니다.
